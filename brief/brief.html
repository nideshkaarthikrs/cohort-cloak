1. Pitch and architecture

An offline, CPU-only pipeline for synthetic Indian hospital exports in English, Devanagari Hindi and Hinglish. It removes personal identifiers, links repeated patient records with keyed pseudonyms, and applies patient-consistent privacy decisions while retaining clinical measurements.

Outputs: sanitized/, report.json, and records.jsonl. Unsupported or unsafe inputs are quarantined and counted; they are never copied as sanitised records.

2. How the components work

  • Ingestion: content sniffing, encoding detection and structured parsing for CSV/TSV, JSON and FHIR bundles, plus text. Input bytes remain unchanged.
  • Detection: clinical guards protect doctors, medicines, doses, labs, vitals and complaints. Validators, multilingual roles, context cues and a learned dictionary locate identifiers across content, keys, headers, filenames and encoded payloads.
  • Linkage: identity evidence and classical similarity feed constrained clustering. Strong contradictions and household-ID handling prevent false merges. HMAC-SHA256 derives pseudonyms from the release secret.
  • Dates: source evidence establishes numeric date order; reliable linked-patient anchors can resolve remaining candidates after linking. One nonzero keyed offset preserves intervals. A missing year is appended only when reliably established and needed for rollover clarity.
  • Privacy: actual exported age bands and locations define anonymity cells. DOB/village redaction and cohort-scaled rare-diagnosis generalisation reduce exposure without altering drugs, lab results or vital measurements.

3. USP and selected trade-off

Learned identity evidence protects multiple channels, while delayed timeline resolution avoids cross-patient date-order contamination. The operating point is selected using a fixed 48-policy grid and a bounded 12-policy follow-up subject to zero practice leaks, no false merges, exact measured intervals, protected-clinical retention and a medical-retention floor.

Selected: 20-year base age bands; top code 75; k = 3; DOB and villages redacted; PIN prefixes subject to escalation; rare diagnoses generalised at 5% of patients, floor 3/cap 8. Procedures and package codes are kept. Optional procedure generalisation is consistent across structured values and prose.

4. Security design

Keys remain in memory. AES-GCM protects spill data; cleanup runs on normal exit, errors and supported signals. Side-channel logs contain enums and counts, never record text or secrets. Linux tests use no network, read-only inputs/root, private temporary storage and fixed resource limits. Ground truth and attacker data are evaluation-only.

6. Independent tests and reproducibility

Blind corpus: an independent author with no code access froze separate tuning and holdout splits. After generic tuning fixes, the untouched 24-file holdout leaked 0/8427 planted PII values. All 1393 medical probes in processed files survived; 278/1671 were lost through four quarantined HTML/XML files. Linkage remains partial: 56/384 oracle patients assigned, 328 unresolved/unexported, no observed false mixed-patient assignments.

Independent privacy probe: correct pure high-confidence heuristic claims fell from 3 to 2 after the policy change. Six of 14 real targets remain unresolved; diagnostic mass bounds are 30.2-73.1%, not official scores or calibrated probabilities.

Independent FHIR: HL7 validator 7.0.8 with pinned R4 definitions found the same 50 errors in 19 raw and released practice bundles (missing categories and unknown custom extensions). No new errors were introduced. A synthetic valid nine-resource-type collection has zero errors before/after. External terminology is disabled; this is not full certification.

Execution: Windows and Linux tests pass. Same input/key gives identical files and mappings across OS/hash seeds; a different key changes outputs. A constrained Linux practice run took 8.8 seconds including startup, about 50 MiB process RSS, network disabled, 2 CPUs, 4 GiB and a 900-second deadline. Inputs remain unchanged; temporary files are cleaned. Required checkers return CONTRACT OK and READY TO SUBMIT.

7. Trade-offs and remaining limits

Targeted re-identification remains possible: exact stays, conditions and hospital context are informative. Wider age bands sacrifice age precision. Overall practice preservation is 96.1%; rare diagnoses and coded descriptions may be generalised. Unknown date order falls back to DMY, and missing years need reliable anchors. Ambiguous multi-patient batches are left unassigned. Novel layouts, severe OCR, larger inputs and the three hidden datasets remain uncertain.
