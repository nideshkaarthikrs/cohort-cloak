CohortCloak: a privacy firewall that links people without exposing them

Track 3 · Secret Wards · Team: Moorthi Annan Gang (Nidesh Kaarthik R S, SRISANJAY G, Prithviraj S, Sai Samanvith G) · Repo: github.com/nideshkaarthikrs/cohort-cloak · Models used: none (rules, gazetteers, classical string similarity)

1. In one paragraph

CohortCloak sanitises a synthetic multi-hospital dump (CSV/TSV, nested JSON, FHIR, English/Hindi/Hinglish text) offline on 2 CPUs. It redacts identifiers in every channel (content, file names, headers, keys, base64, encodings), keeps clinical values exact, gives each patient one keyed pseudonym across all files, and then measures its own re-identification risk with a re-implemented registry attacker and picks its privacy settings from that measurement. Its single best idea: a two-pass design, learning every name and ID from structured fields first and then using them everywhere, with cluster-level privacy decisions applied after linkage.

2. Architecture

Flow. input/ (any format, any encoding) → Ingest (sniff, decode, quarantine) → Detect (pass 1 learns names, IDs, ID shapes and date order from every channel; pass 2 renders with placeholders that carry payloads) → Link (blocking, Fellegi-Sunter scores, constrained clusters, HMAC pseudonyms) → Privacy plan (per-patient date shift, age band, rare-diagnosis and k-anonymity decisions, resolved per patient) → Outputs: sanitized/, report.json, records.jsonl, logs with enums only. A linking failure degrades to "unlinked but complete"; a file failure to quarantine with a snake_case reason.

3. How it works

  • Ingestion: sniff by content, not extension; utf-8/BOM/UTF-16/cp1252 with a mojibake check; JSON behind a .csv name is parsed as JSON; empty, binary, XML/PDF/JPG, truncated, 1,500-deep and bad-encoding files are quarantined (never copied) with a reason code.
  • Detection: clinical guards first (doctors, doses, 1-0-1, vitals, ranges, ICD, wards, C/O fever vs C/O Ramesh, K/C/O, eponyms); hard identifiers (phones incl. Devanagari digits, Aadhaar, ABHA, PAN, shape-induced IDs) override guards. Column/key roles come from multilingual header synonyms plus a value profile (values beat headers). Names: run-time dictionary matched across spellings and scripts by phonetic skeletons (Rina/Reena, Mohd/Mohammad/मोहम्मद), cues (S/o, W/o, ji/sahab, ko/ne, "called by", WhatsApp senders, name-near-phone), gazetteers, and a fail-closed rule for two unknown capitalised words. Work happens on a normalised shadow (homoglyphs, zero-width, diacritics) and decodes base64, %-encoding, \u escapes and entities.
  • Linkage and pseudonyms: per-record evidence, blocking on IDs, phones, DOB and name skeletons, hand-set Fellegi-Sunter weights, hard cannot-links, demotion of household/attendant IDs, constrained clustering with an ambiguity margin, a unique-match rule for fragments, PSN- + HMAC-SHA256 keyed by RAKSHA_SECRET.
  • Privacy layer: per-patient date shift (stays and intervals exact, any format and Hindi months), cluster-consistent 5-year age bands, rare-ICD generalisation to category/chapter, k-anonymity escalation, DOB and village redacted, PIN to 3 digits.
  • Security: keys derived in memory by HKDF; AES-GCM spill; no PII or secret in stdout, stderr, logs, report, temp files; the input is read-only; exception text is never recorded, only class names.

4. USP

  • Learn-then-redact across channels: every structured name/ID protects file names, keys, headers, prose and base64, so unseen names in structured fields cannot leak elsewhere.
  • Measured privacy: attack_sim.py re-implements the registry attacks; sweep.py chose the settings by a privacy-utility score, not by guess.
  • Honest generalisation tests: generated stress sets (new names, headers, formats, hidden channels, canaries, new layouts) with their own truth.

Why these settings. The sweep (tools/sweep_results.md) scores each choice by 25(1-risk)·min(1,U/0.4) + 20U. Redacting DOB cut A4 from 25% to 2% at a cost of about 0.01 in utility; k-anonymity cut A4 from 54% to 2%; redacting the village instead of keeping the district cut A4 from 17% to 2%. Rare diagnoses are the open trade-off: a fixed threshold of 8 lowers the targeted attack to 17% of raw but keeps only 89% of medical values, while our cohort-scaled threshold (floor 3, cap 8) keeps 94.7% and leaves A5 at 48%. We chose to protect clinical utility and flag the gap; larger cohorts push the threshold up automatically. Date intervals and stay lengths are never traded away.

6. Security design

Assume the server will be breached: temporary data is encrypted (AES-GCM, key = HKDF of the release secret, never stored) and deleted on exit, errors and SIGTERM; pseudonyms are keyed HMACs, so unkeyed hash dictionaries (the arena's A6) fail and a new secret yields new pseudonyms and new date shifts (A7). Logs carry only enums and integers; failures write a class name, never content. Files we cannot process are quarantined, never copied, and always listed in report.json by SHA-256.

7. Known limitations (honest list)

  • Targeted attack: A5 stays at 48% of raw on 48 patients; length of stay cannot be hidden by design, and rare conditions are only generalised below the scaled threshold.
  • New layouts: unseen document layouts are the main risk; our stress sets and attacker are our own work, not the organisers' evaluator, and the unseen-layout result above shows how fast it can fall (43% name leak) before tuning.
  • Gaps: procedures and package codes are generalised only in structured fields; OPD file names keep the month; memory grows with the number of events (about 1.1 GB and 81 s for 36 MB of repeated dev data, measured in Docker at 2 CPUs / 4 GB).
  • Tuning: linkage weights, thresholds and the operating point were tuned on the practice data; generalisation score is low by design (DOB, village, PIN prefix are redacted or coarse).
  • Next steps: a held-out layout set from a second author, spilling the event table, procedure/package generalisation, and a learned scoring layer for linkage if allowed.
